# Project Rubric

Use this project rubric to understand and assess the project criteria.

## Design Pattern Implementation

### Criteria

Implements Singleton Pattern for Balance Management

### Submission Requirements

A Singleton Balance class is implemented correctly to ensure only one instance of the balance exists across the application.

### Criteria

Implements Adapter Pattern for External Transactions

### Submission Requirements

An ExternalFreelanceIncome class and TransactionAdapter are included. Adapter correctly converts external data to internal Transaction objects.

### Criteria

Implements Observer Pattern for Low Balance Alerts and Balance Changes

### Submission Requirements

A LowBalanceAlertObserver class is implemented and registered to the Balance class. Alert is triggered when balance falls below a defined threshold. Additionally, a PrintBalanace class is implemented and registered to the Balance Class. Balance is printed when a new transaction is applied.

### Criteria

Implements a Fourth Design Pattern (Student’s Choice)

### Submission Requirements

Student selects and implements one additional design pattern that hasn’t been used already and documented the use clearly.

## Industry Best Practices

### Criteria

Demonstrates Effective Unit Testing

### Submission Requirements

Unit tests are written for Balance, Transaction, the Adapter, Observer, and custom pattern. Tests run without errors.

### Criteria

Project Runs Successfully and Applies Transactions

### Submission Requirements

Running the main.py file simulates processing transactions and reflects updated balance and alerts.

### Criteria

Code is Clean, Modular, and Pythonic

### Submission Requirements

Code follows PEP8 standards, uses idiomatic Python, and organizes classes by file and function. No large functions or excessive duplication.

## Reflection

### Criteria

Student Provides a Reflection and Pattern Rationale

### Submission Requirements

A short written reflection is included explaining the 4 patterns used, why each was chosen, and any trade-offs or challenges.

## Suggestions to Make Your Project Stand Out

- Add Undo/Redo Capability with Command Pattern - Implement command objects for applying transactions, and allow users to undo the last transaction.
- Add a Strategy for Budget Planning - Let users choose between budgeting strategies (e.g., "50/30/20 Rule", "Zero-Based Budgeting") and apply those strategies dynamically.
- Introduce Transaction Validation or Logging Decorator - Use a decorator to log each transaction or validate inputs before applying to the balance.
